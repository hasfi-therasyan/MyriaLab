About MyriaLab

Where the name comes from.

A myriad is a number too large to finish counting. We built a software company around that idea instead of around one fixed roadmap.

MyriaLab started as an argument between two engineers about how many ways there were to solve the same caching problem. The honest answer was more than either of us had tried, and neither of us wanted to stop at the first one that worked.

The name followed from there. Myria, from myriad: a number large enough that you stop trying to count it exactly. Lab, because none of this started as a finished product. It started as something we were still testing.

Build software that still holds up after the people who approved the budget have moved on to the next thing.

We'd rather ship the boring, correct version than the impressive one that needs a rewrite in a year.

How we work.

Four principles that shape the day-to-day, not a poster in a hallway.

Craftsmanship over velocity theater

Shipping fast is only worth something if what ships is still worth maintaining six months later.

Delete code as readily as we write it

An unused branch, a dead feature flag, a config nobody reads: if it doesn't earn its keep, it goes.

Iterate where it's cheap to be wrong

We'd rather be wrong in a prototype on Tuesday than wrong in production during a client's busiest week.

Boring technology, used well

Novelty is a cost we only pay when the problem actually requires it, not because a framework is new.
